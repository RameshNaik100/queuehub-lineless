# QueueHub — LineLess

**Join. Track. Get notified. Show up when it’s your turn.**

QueueHub — LineLess is a smart virtual queue management platform designed for **PS02: Smarter Queues & Shared Services**. It helps organizations replace physical waiting lines with digital, service-specific queues that customers can join using a QR code or link.

## Problem

People often spend unnecessary time waiting in physical queues at colleges, offices, service centers, and other shared-service environments.

Organizations also need a simple way to manage multiple services, staff members, counters, and customer queues while keeping customers informed about their position and estimated waiting time.

---

## Proposed Solution

QueueHub — LineLess creates a digital queue for each service.

Organizations can:

* Create and manage services
* Publish service-specific customer links
* Generate and share QR codes
* Create staff accounts
* Monitor live queues
* Call, complete, skip, and recall customers
* Track service activity and waiting times

Customers can:

* Join without creating an account
* Scan a QR code or open a service link
* Receive a queue token
* See their position and estimated wait
* Follow live queue updates
* Receive status notifications

## Key Features

### Organization & Staff

* Organization registration and isolated workspaces
* Admin and staff role separation
* Staff account management
* Organization-level service management
* Organization deletion support

### Digital Queues

* Multiple customers can join the same service queue
* Real queue tokens generated by the backend
* Queue position and estimated waiting time
* Live now-serving status
* Call Next
* Complete
* Skip / No-show
* Recall
* Pause / Resume
* Priority request and staff verification

### QR & Sharing

* Service-specific customer links
* Real scannable QR codes generated locally
* QR download
* Link copying and sharing
* Customer access without a QueueHub account

### Live Updates

* WebSocket-based queue updates
* Shared queue state across browsers and devices
* Automatic queue position and ETA updates

### Service Reset

* Updating a service starts a fresh active queue
* Previous waiting/served customers are removed from the active queue
* New customers can join the refreshed queue
* Other services remain unaffected

### User Experience

* Responsive desktop, tablet, and mobile interface
* Clear loading, success, error, and empty states
* Mobile-friendly customer queue view
* Modern dashboard and queue controls

## How It Works

```text
Organization
     ↓
Create Service
     ↓
Publish Service
     ↓
Generate QR / Customer Link
     ↓
Customer Scans QR or Opens Link
     ↓
Customer Joins Queue
     ↓
Token Generated
     ↓
Staff Calls Customer
     ↓
Customer Served / Skipped
     ↓
Queue Updates Live
```

---

## System Architecture

```text
Customer Browser ─────┐
                      │
Staff Dashboard ──────┼──→ Node.js HTTP Server
                      │             │
Admin Dashboard ──────┘             ├── REST-style JSON APIs
                                    ├── WebSocket Updates
                                    │
                                    ↓
                              SQLite Database
```

The backend acts as the shared source of truth for organizations, services, customers, queue entries, service records, and queue history.

WebSockets are used to broadcast queue changes to connected clients.

* Node.js 22+

## Demo Workflow

For a complete demonstration:

1. Register an organization.
2. Log in to the admin workspace.
3. Create and publish a service.
4. Open the generated customer link or QR code.
5. Join the queue as one or more customers.
6. Open the staff dashboard.
7. Select the service.
8. Use **Call Next**.
9. Complete or skip customers.
10. Observe the queue position and status update for connected customers.
11. Update the service to demonstrate the fresh-queue behavior.
12. Generate a new customer link/QR when required.

---

## Security

The prototype is designed with organization-scoped access and role separation.

For a production deployment, additional security hardening would include:

* Secure password hashing
* HTTPS
* Secure session management
* Rate limiting
* Strong request validation
* Production-grade authentication and authorization
* Managed database credentials through environment variables
* Database backups and monitoring

**No passwords, API keys, AWS keys, or database credentials are stored in the GitHub repository.**

---

## Current Limitations

* SQLite is suitable for the prototype but is not ideal for large-scale production workloads.
* The current deployment uses a prototype-level authentication model.
* Production deployment would require stronger security controls and persistent managed database infrastructure.
* Render's free deployment environment is intended for demonstration rather than production-scale persistent workloads.
